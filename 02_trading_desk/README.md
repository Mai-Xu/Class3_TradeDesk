# 项目 2 · 交易台可视化

用上交所 Level-2 逐笔数据复现交易所撮合，与交易所快照逐档核对，
并把逐笔回放渲染成一个**单文件交互式"交易台"页面**。

本目录包含两层内容：

1. **撮合复现与数据核对引擎** —— `engine.py` / `replay.py` / `run_reconcile.py` / `datadir.py`
2. **交易台可视化** —— `build_dashboard.py` + `trading_desk_template.html` → `交易台可视化.html`

数据目录通过 `--data-dir` 或环境变量 `SSE50_DATA_DIR` 指定，代码中无本机绝对路径；
原始数据由课程 Release 下载，本目录不重复包含。

## 文件

| 文件 | 说明 |
| --- | --- |
| `engine.py` | 价格-时间优先订单簿：挂单/撤单、连续竞价撮合、集合竞价撮合、十档快照 |
| `replay.py` | `replay_auction`（集合竞价复现）、`reconstruct_book`（委托+成交 → 订单簿 → 快照） |

| `make_report.py` | 由指标生成 `report.md` |

| `trading_desk_template.html` | 页面模板（含 `//__MARKET_DATA__` 占位符） |
| `交易台可视化.html` | **成品**：约 17 MB 自包含页面，双击即开 |
| `交易台预览.png` | 页面截图 |
| `report.md` / `metrics.csv` / `metrics_curve.json` | 核对报告与逐股指标 |

## 运行

```bash
# 重建数据并渲染页面（约 3 分钟）
python build_dashboard.py --data-dir /path/to/sse50_20260923

# 只用已有的 market_data.js 重新渲染模板
python build_dashboard.py --render-only

# 重新跑 50 只的逐档核对，生成 metrics.csv / report.md
python run_reconcile.py --data-dir /path/to/sse50_20260923
python make_report.py
```

不传 `--data-dir` 时按以下顺序自动定位：环境变量 `SSE50_DATA_DIR` / `OBSIM_DATA_DIR`
→ 本项目同级 `sse50_*` → 当前目录 → 向上搜索 `ord_*.parquet`。

## 核对结果

### 十档行情快照

逐笔消息与 3 秒快照之间存在一个随消息速率变化的微小时间偏移（行情网关队列延迟，约 0.15–1.0 秒）。
用上午行情校准该偏移、在下午做**样本外**评价：

| 指标 | 未校正 | 校准后（上午，样本内） | 校准后（下午，样本外） |
| --- | ---: | ---: | ---: |
| 最优买卖价完全一致 | 84.7% | 94.9% | **93.2%** |
| 十档价格一致 | 87.9% | — | **94.1%** |
| 十档价 + 量完全一致 | 81.4% | 94.4% | **92.6%** |

中位数（样本外）：最优价 95.1%、十档价+量 94.0%。
未命中样本集中在成交极活跃、消息速率高的标的（如 600183）。

### 集合竞价

50 只标的的开盘与收盘集合竞价**全部逐笔一致**——笔数、价格、买卖双方订单号逐条对应，
合计 38,867 笔，precision = recall = 100%。

- 开盘集合竞价（9:15–9:25 的委托在 9:25 撮合）**只用逐笔委托**即可完整还原；
- 收盘集合竞价（14:57–15:00）需要先用"逐笔委托 + 成交回报"把 14:57 的订单簿重建出来再撮合。

## 关键设计

### 委托与成交的联合处理

- 新增委托建单入簿，撤单按被撤数量减量；
- 成交按方向扣减**被动方（挂单方）**，集合竞价成交扣减双方。

**为什么只扣被动方**：上交所逐笔委托只披露"进入订单簿"的委托，
一笔成交里挂单方在 `ord` 中命中率约 99.9%，而主动成交方只有约 8%；
且新增委托记录可能已是"立即成交后的剩余挂单量"，
因此不能再把成交量从后出现的剩余挂单里重复扣减一次。

### 集合竞价定价

最大成交量定价；并列时取未成交量最小，再取中间价；同一价格内按价格-时间优先撮合。

## 字段语义（已实测确认）

- `ord.FunctionCode`：`66`='B' 买、`83`='S' 卖；`73/79/74/67/86` 为阶段标记（每标的各 1 条）。
- `ord.OrderKind`：`65`='A' 新增、`68`='D' 撤单（`Volume` 为被撤数量）、`83`='S' 状态。
- `ord.OrderOriNo`：交易所订单号，**按频道分配**（同一号码会在不同股票出现）。
- `exe.BidOrder` / `AskOrder` 引用 `ord.OrderOriNo`；`exe.BSFlag` `0` = 集合竞价成交。
- `Channel` `2301` 为盘后固定价格交易（15:05–15:30，价格取当日收盘价）。

## 注意

- `market_data.js`（约 18 MB）是可再生中间产物，未入库；
  成品页面已内联全部数据，**不需要它也能打开**。只有 `--render-only` 才会用到。
- 时间对齐只用于离线核验，不用于让策略提前获得未来盘口。
- 抽样核对不等于证明所有时间点的数据完整性。
